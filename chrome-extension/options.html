External KB search

The /knowledge slash command can surface "Search the external KB" shortcuts — pre-filled queries for the customer's own knowledge portal (e.g. Thermo Fisher's knowledge1.thermofisher.com). Set the URL template here; {query} is replaced with the URL-encoded search string. Leave blank to hide the external-search section.

Examples: https://knowledge1.thermofisher.com/Special:Search?search={query} (MindTouch — the standard for Thermo Fisher's knowledge base), https://www.google.com/search?q={query}, https://your-confluence.atlassian.net/wiki/search?text={query}.

Verify the right format for your KB: run a manual search in your KB, copy the URL of the results page, and substitute the search term with {query}. For MindTouch (used by knowledge1.thermofisher.com), the correct path is /Special:Search?search= — NOT /search?q=.

KB direct mode (bypass Azure AD)

Call the external knowledge base directly from Chrome using your existing browser session — no Azure AD app registration required. You must be signed in to the KB in another Chrome tab. Useful when the shim doesn't have Azure credentials configured.

Leave blank to keep using the shim's KB connector. When set, /kb and /kb-ticket route directly to <url>/@api/deki/site/search with your existing session cookies. If you see Not signed in, open the KB in a Chrome tab, log in via SSO, then retry. The host must be in the extension's host_permissions — knowledge1.thermofisher.com and *.thermofisher.com are pre-granted.

Parts-ordering processing type code

Used by /order-parts when committing line items to SAP via log_service_item. This is for Parts Ordering, not Parts Consumption — two distinct SAP workflows. Default ZRP3 for tenants using Thermo Fisher's Z-prefix customer extension pattern (Parts Ordering). Other tenants may use ZRP1, ZSRP, or similar codes for parts ordering. If you see "unknown message type" errors with the right code, the rejection is usually a missing required field in the POST body (e.g., ItemCategoryCode, BusinessTransactionDocumentItemTypeCode) — ask your SAP admin which fields are mandatory for parts-ordering line items on ServiceRequestItemCollection on this tenant, and check the shim console for the full SAP response.

Parts-inference: include processing types

When /order-parts auto-suggests parts by scanning similar past tickets, only line items with one of these processing- type codes count toward the recurrence calculation. Default SRP1,ZRP1 — parts consumption codes (parts that were actually used). Excludes ZRP3 (parts ordered but not yet consumed), ZALT (labor), SRPT (service total), REMOTE_DIAGNOSTIC, etc. Comma-separated. Codes are matched case-insensitively. Set blank to disable the line-item path and use the LLM resolution-notes path only.

SLA Watcher

Poll the C4S shim on a schedule and surface tickets whose SLA is about to breach. When a new ticket crosses the threshold you get a desktop notification (click to open it in the side panel) and the toolbar icon shows the count. De-duped — you won't get re-notified for the same ticket on every poll.

A ticket is "at risk" when its SLA breach is within this many hours. Default 24 — sensible for most service desks. Lower values (6-12h) give tighter notifications; higher (48-72h) gives more lead time. Min 1, max 168 (1 week).
How often to check. Chrome enforces a 5-minute minimum for background polling, and we cap at 60. Default 15.

Auto Customer Pulse

Fire /pulse automatically as soon as the side panel or popup detects a SAP ticket — surfaces a Customer Pulse card at the top of the panel with a 🟢/🟡/🔴 health score, reasons (recent SLA misses, repeat issues, negative tone in past notes), and 3-4 personalised handling suggestions for THIS ticket. Independent of auto-triage and auto-KB — renders to its own card area so they can all run together. Results cached per-customer for 2 hours.

Auto-triage

Fire /triage automatically as soon as the side panel or popup detects a SAP ticket — no need to type the slash command yourself.

Once per ticket remembers tickets you've already triaged in this browser session and skips them — avoids burning tokens re-triaging the same ticket every time you click into it.

Auto-fetch KB articles

Fire /kb-ticket automatically as soon as the side panel or popup detects a SAP ticket — pulls related knowledge-base articles without you needing to type the slash command. Mutually exclusive with auto-triage: if both are enabled, auto-triage wins and KB auto-fetch is skipped (so they don't fight for the reply box).

Once per ticket remembers tickets you've already KB-fetched for in this browser session and skips them — avoids re-running the same KB search every time you click into a ticket.

Auto-fetch KB resolutions (deep)

Fire /kb-resolve automatically when a ticket is detected — the deep variant that searches the KB across 5 query angles, fetches the top article bodies, and uses the LLM to extract the actual fix steps per article. Slower than /kb-ticket (~8-12s) but surfaces the answer, not just the titles. Requires KB direct mode configured (see "KB direct mode" section above). Mutually exclusive with auto-triage and auto-fetch KB articles; precedence is auto-triage > auto-kb-resolve > auto-kb-ticket.

Silently skipped when KB direct mode isn't configured — no point firing a command that'd just info-fail. Set the base URL in KB direct mode first.

Saved templates

Templates appear as chips in the popup/side panel — click one to fill the prompt textarea. Built-in templates ship with the extension; hiding one removes the chip but doesn't delete it. Your own templates sync via your Chrome profile across devices.

Tip: use ⋯ → ⭐ Save as template in the panel's action bar to add a new template from whatever prompt you've just typed.
Chips reorder by how often you use them. This resets to the default order.
